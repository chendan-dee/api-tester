本仓库未定义统一的异常类型或错误码体系，而是采用「函数返回结果字典 + 结构化错误列表」的轻量级错误处理模式，贯穿 CLI、Web 和核心引擎三层。

## 1. 核心模式：结果字典（Result Dict）

`engine.py` 中的 `do_request` 统一返回一个包含固定字段的字典：
- `ok: bool` — 请求是否成功
- `status_code / elapsed_ms / resp_text / resp_json / resp_headers` — 正常响应数据
- `error: str | None` — 错误信息；为空表示无错
- `is_mock: bool` — 是否为模拟响应

调用方（`_run_step_once`、`run_single`、`app.py` 的 `/api/run` 等）通过检查 `result["error"]` 分支处理失败路径，而非抛出异常。HTTP 层将 `requests.exceptions.Timeout` 和其他 `Exception` 捕获后转为 `error` 字符串，保证上层逻辑始终走同一条“成功/失败”分支。

## 2. 前置条件（setup）错误：结构化错误列表

`eval_setup` 对每个 Python 表达式独立执行，单个失败不影响其他变量计算。它返回 `(variables, errors)` 二元组，其中 `errors` 是形如 `[{"name","expr","error"}, ...]` 的结构化列表。该列表在 CLI 中通过 `printer.print_setup_error` 打印，在 Web 端通过 `/api/run` 和 `/api/run-stream` 的 `setup_errors` 字段返回给前端展示。

## 3. YAML 解析与校验错误

- `runner.py::load_yaml`：缺少依赖时 `print` 提示并 `sys.exit(1)`；文件不存在同样直接退出。
- `app.py` 的 `/api/load`、`/api/validate`、`/api/save`、`/api/append`、`/api/step/update` 等接口：捕获 `yaml.YAMLError`，提取 `problem_mark.line/column`，以 JSON `{ok:false, error, line, col}` 形式返回，由前端渲染行号定位。
- `yaml_checker.py` 提供业务规则校验，返回 `[(location, problem, fix), ...]` 三元组列表，被 `/api/validate` 包装为 `errors` 数组返回。

## 4. Web 层错误策略

Flask 路由内部不抛异常，所有错误均以 `jsonify({"ok": False, "error": "..."}), status_code` 形式返回（常见状态码 400/404）。流式接口 `/api/run-stream` 在生成器中发送 `data: [DONE]` 标记完成，中间步骤错误仍作为普通记录事件推送，不会中断 SSE 流。

## 5. 约定与约束

- **禁止 raise**：核心执行路径不使用 `raise`，错误一律下沉到结果结构体中，避免跨模块异常传播。
- **错误可序列化**：所有错误信息最终都是字符串或可 JSON 序列化的字典，便于终端输出和 HTTP 响应复用同一数据结构。
- **断言失败 ≠ 异常**：`run_assert` 返回 `(passed, messages)`，断言失败仅影响 `passed` 标志，不中断流程。
- **缺失依赖降级**：`pandas` 不可用时保存回退 CSV；`colorama` 不可用时禁用彩色输出；`pyyaml` 缺失时 CLI 直接退出。

## 关键文件

- `engine.py` — 结果字典、setup 错误列表、HTTP 异常转 error 的核心实现
- `printer.py` — 错误信息的终端呈现（`print_error`、`print_setup_error`、`warn`）
- `runner.py` — CLI 入口，依赖缺失与参数错误的快速失败
- `app.py` — Web 层 YAML 解析错误、业务校验错误、运行错误的 JSON 化返回
- `yaml_checker.py` — 配置结构的语义校验，返回结构化错误三元组
